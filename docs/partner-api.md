# Partner API

Hotels, PMS vendors and travel partners use the API to list nearby places, report how guests interact with them, and claim vouchers for their guests.

The full reference, with every field and response, is generated by Scramble at **`/docs/api`**. Only admins can open it. This page is the overview.

## Integrations and keys

An admin creates an **integration** under `/admin/integrations`:

| Setting      | Values                                                                        |
| ------------ | ----------------------------------------------------------------------------- |
| Type         | `pms`, `travel_agency`, `internal`                                            |
| Capabilities | see below                                                                     |
| Status       | active or suspended. While suspended, every key of the integration is refused |

Then the admin creates an API key on the integration's **API keys** tab. The full key is shown **once**. Only a hash is stored, so a lost key must be rotated. Keys can be rotated and revoked at any time.

Send the key as a bearer token:

```http
GET /api/v1/outlets HTTP/1.1
Host: app.example.com
Authorization: Bearer <api-key>
Accept: application/json
```

## Capabilities

Each endpoint needs one capability on the integration. A key without it gets `403 forbidden`.

| Capability         | Allows                          |
| ------------------ | ------------------------------- |
| `places:read`      | Lookups, list and show outlets  |
| `engagement:write` | Send engagement events          |
| `vouchers:read`    | List an outlet's voucher offers |
| `vouchers:claim`   | Claim, show and void vouchers   |

## Endpoints

All paths start with `/api/v1`.

| Method | Path                             | Capability         |
| ------ | -------------------------------- | ------------------ |
| `GET`  | `/categories`                    | `places:read`      |
| `GET`  | `/tags`                          | `places:read`      |
| `GET`  | `/states`                        | `places:read`      |
| `GET`  | `/outlets`                       | `places:read`      |
| `GET`  | `/outlets/{slug}`                | `places:read`      |
| `POST` | `/engagement-events`             | `engagement:write` |
| `GET`  | `/outlets/{slug}/voucher-offers` | `vouchers:read`    |
| `POST` | `/voucher-offers/{offer}/claims` | `vouchers:claim`   |
| `GET`  | `/vouchers/{voucher}`            | `vouchers:claim`   |
| `POST` | `/vouchers/{voucher}/void`       | `vouchers:claim`   |

### Lookups

`/categories`, `/tags` and `/states` return the slugs the outlet filters accept. They change rarely, so cache them. States are the Malaysian states and federal territories.

### Outlets

Only **public** outlets are returned: approved, listed by the owner, complete, and not hidden by an admin. An outlet that stops being public drops out of the list and returns `404`.

| Parameter               | Meaning                                      |
| ----------------------- | -------------------------------------------- |
| `filter[category]`      | Any of these category slugs, comma-separated |
| `filter[tag]`           | Every one of these tag slugs                 |
| `filter[state]`         | Any of these state slugs                     |
| `filter[search]`        | Matches name or summary                      |
| `filter[updated_since]` | RFC 3339 time with a timezone                |
| `sort`                  | `name` or `updated_at`                       |
| `per_page`              | 1–100, default 25                            |

An unknown filter value is refused, not answered with an empty list, so a typo shows up.

Lists are **cursor-paginated**: follow `links.next` (or pass `meta.next_cursor` as `cursor`) until it is null.

To sync, pass `filter[updated_since]` with the time of your last sync and `sort=updated_at`. An outlet that stops being public never appears in a sync, so run a full sync now and then to drop those.

### Engagement events

Send what guests do with a place on your site, in batches of 1 to 100:

```json
{
    "events": [
        {
            "event_type": "place_view",
            "outlet": "kopi-waterfront",
            "session_ref": "your-session-id",
            "external_event_id": "evt_0001",
            "occurred_at": "2026-09-26T10:15:00+08:00"
        },
        {
            "event_type": "outbound_click",
            "outlet": "kopi-waterfront",
            "session_ref": "your-session-id",
            "external_event_id": "evt_0002",
            "occurred_at": "2026-09-26T10:15:30+08:00",
            "metadata": { "destination_type": "whatsapp" }
        }
    ]
}
```

| Field                       | Notes                                                                                     |
| --------------------------- | ----------------------------------------------------------------------------------------- |
| `event_type`                | `place_impression`, `place_view` or `outbound_click`                                      |
| `outlet`                    | A public outlet's slug                                                                    |
| `session_ref`               | Your own reference for the visitor's session. Stored only as a one-way hash               |
| `external_event_id`         | Optional. An ID you already sent is skipped, so a batch can be resent safely              |
| `occurred_at`               | RFC 3339 with a timezone                                                                  |
| `metadata.destination_type` | Only for `outbound_click`: `map`, `phone`, `website`, `whatsapp`, `facebook`, `instagram` |

If any event is invalid, **none** is stored and every error is returned. A valid batch returns `202`.

### Voucher offers

`GET /outlets/{slug}/voucher-offers` lists the offers a guest can claim now and use at that outlet: running, inside their dates and not fully claimed. Soonest ending first, cursor-paginated.

### Claim a voucher

```http
POST /api/v1/voucher-offers/{offer}/claims
```

```json
{
    "guest_ref": "booking-48213",
    "idempotency_key": "claim-7f3c2a",
    "outlet": "kopi-waterfront"
}
```

| Field             | Notes                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `guest_ref`       | Your own reference for the guest. Stored only as a one-way hash                                                          |
| `idempotency_key` | A new key for each claim                                                                                                 |
| `outlet`          | Optional. The outlet you showed the guest. It records where the claim came from and never limits where the voucher works |

The response's `data` holds `claim_status`, `voucher`, `code` and `qr_value`:

| `claim_status`      | HTTP | Code returned? | When                                                             |
| ------------------- | ---- | -------------- | ---------------------------------------------------------------- |
| `created`           | 201  | ✅             | A new voucher                                                    |
| `idempotent_replay` | 200  | ✅             | Same `idempotency_key`, same body — the first voucher again      |
| `existing_active`   | 200  | —              | The guest already holds an active voucher of this offer from you |

With a code, the response has `code` (shown as `ABCDE-12345`) and `qr_value` (`V1:ABCDE12345`). Give the guest the code or show `qr_value` as a QR code; the counter accepts both.

> [!IMPORTANT]
> The code is returned only with `created` and `idempotent_replay`. `GET /vouchers/{voucher}` never returns it. Store it, or give it to the guest, straight away.

Errors specific to claims:

| HTTP | `code`                 | When                                         |
| ---- | ---------------------- | -------------------------------------------- |
| 409  | `idempotency_conflict` | Same `idempotency_key` with a different body |
| 409  | `offer_limit_reached`  | The offer has no vouchers left to give       |

### Show and void

- `GET /vouchers/{voucher}` returns a voucher **your integration** claimed, without the code.
- `POST /vouchers/{voucher}/void` cancels it for good. Send `reason_code`: `guest_cancelled`, `duplicate_claim`, `issued_in_error` or `suspected_abuse`. A voucher that is used, void or expired fails with `409 voucher_not_active`.

## Errors

Every error has one shape:

```json
{
    "errors": [
        { "path": "/events/0/outlet", "code": "unavailable", "message": "..." }
    ]
}
```

- `path` is a JSON pointer to the input field, or empty for the whole request.
- `code` is stable — branch on it. `message` is for people and may change.

| HTTP | `code`                                                              |
| ---- | ------------------------------------------------------------------- |
| 400  | `invalid_query`                                                     |
| 401  | `unauthenticated`                                                   |
| 403  | `forbidden`                                                         |
| 404  | `not_found`                                                         |
| 409  | `idempotency_conflict`, `offer_limit_reached`, `voucher_not_active` |
| 422  | `required`, `invalid`, `unavailable`                                |
| 429  | `rate_limited`                                                      |
| 500  | `server_error`                                                      |

## Limits and tracing

- **300 requests a minute** per integration.
- Every response has an `X-Request-Id` header. Send your own `X-Request-Id` and it is echoed back when safe. Quote it when you report a problem — it is on every log line for the request.

## Privacy

AroundThat never receives a guest's name, email or booking details. `guest_ref` and `session_ref` are stored only as one-way hashes, and businesses see counts, not people.
